# План: модернизация кабинета мастера

Источник истины: `docs/PRD.md` F-31, F-19, F-14, S1; `docs/TECH-DESIGN.md` §18 (касса), §20 (роуты), §23 (токены).

Календарь и записи уже в современном визуальном языке (`bookings.module.css`, календарные вкладки). Касса, хаб, онбординг и уведомления отстают. Дифференциатор продукта — **личная касса** — спрятан и выглядит как админ-форма.

## Что уже хорошо

- Календарь: день/неделя, блоки, ручная запись.
- Записи: вкладки, CTA «Записать клиента», деталь визита.
- Клиенты: поиск и «Частые».
- Касса **на бэкенде**: автодоход с `completed`, системные категории, чаевые с `bookingId`, расходы за период.
- Публичные `/catalog` и `/m/[slug]`: RSC + острова.

## Главные дыры UX

1. **Касса не находится.** На мобилке 5 слотов нижней панели: Кабинет / Календарь / Записи / Портфолио / Ещё. Касса только в «Ещё» и одной ghost-кнопке хаба. Клиенты кассу не должны видеть — но **мастер** должен спотыкаться об неё каждый день.
2. **Экран кассы — таблица без продукта.** Нет графика, нет карточек итога в стиле записей, форма «новая строка» всегда на экране (тип, категория, своя метка, сумма, комментарий). Чаевые к визиту API умеет, UI — нет. `occurredOn` для чаевых берётся с конца периода, а не с даты визита.
3. **Нет мостика «визит → деньги».** «Завершить визит» пишет доход в кассу молча. Нет «добавить чаевые», нет подсказки в календаре и в списке записей.
4. **Онбординг ≠ PRD S1.** Шаг портфолио — ссылка на другую страницу. Нет фото в профиле, нет превью `/m/[slug]` в конце.
5. **Уведомления.** Бэкенд (Telegram, напоминания 24/2 ч) есть. В кабинете — только карточка «привязать Telegram». Нет inbox и настроек каналов.
6. **Кабинет `/app/**` — всё client-fetch.** TECH-DESIGN обещает prefetch на сервере. Двойной `loadSession` в шапке и фрейме. Нет скелетонов.

## Информационная архитектура (мобилка)

Нижняя панель остаётся из **5** ячеек. Ежедневные операции вытесняют редкие:

| Слот | Было | Станет |
|---|---|---|
| 1 | Кабинет | Кабинет |
| 2 | Календарь | Календарь |
| 3 | Записи | Записи |
| 4 | Портфолио | **Касса** |
| 5 | Ещё | Ещё |

«Ещё»: Клиенты, Портфолио, Отзывы, **Профиль**, Первые шаги (пока онбординг не `done`). Каталог как сейчас.

Портфолио не пропадает: оно в «Ещё» + онбординг + хаб. Загрузка фото — не ежедневный жест, в отличие от «сколько я заработала».

Десктоп (≥768px): полный rail, Касса выше Портфолио.

## Волны

### Волна 1 — касса как продукт + discoverability (этот PR)

Цель: мастер **видит** кассу, **понимает** зачем она, **вносит** чаевые и расход за 2–3 тапа, видит картину периода.

- Касса в primary-nav; Профиль в «Ещё».
- Дашборд: карточки Доход / Расход / Итог, CSS/SVG-график по дням (неделя) или неделям (месяц), разбивка по категориям.
- Добавление — bottom sheet, не вечная форма. Быстрые кнопки: Чаевые / Материалы / Аренда.
- Хаб: снимок кассы за месяц (цифры + ссылка), не ghost в подвале.
- Завершённый визит: карточка «визит в кассе → добавить чаевые».
- Короткие подсказки в календаре, списке записей, профиле.
- Фикс: чаевые пишутся на сегодня / дату визита, не на конец выбранного периода.

Без новой библиотеки графиков. Без F-19 (загрузка слотов, конверсия). Без смены контракта API, кроме уже существующего `bookingId`.

### Волна 2 — онбординг и фото

- Шаг 4: загрузка 1–3 фото внутри визарда, не уход на другую страницу.
- Финал: превью публичной ссылки, копирование, CTA Telegram.
- Портфолио: прогресс по файлам, подпись, опциональный кроп под cover.

### Волна 3 — уведомления как поверхность

- Блок «Как приходят записи» в профиле: Telegram (есть) + честно «email — fallback, в работе» (F-15).
- На детали записи — статус «клиенту уйдёт напоминание за 2 ч», без dev-probe в проде.
- In-app inbox — не в MVP этой модернизации (F-18/F-22 ближе).

### Волна 4 — скорость кабинета

- Prefetch сессии и кассы/записей в RSC-обёртках `/app/master/*` (как публичный `/m/[slug]`).
- Один `loadSession` на кабинет, не два.
- Скелетоны списков в языке записей.

### Волна 5 — аналитика F-19 (отдельно от кассы)

Касса = факт денег. Аналитика = загрузка часов, повторные клиенты, просмотры → брони. Отдельный экран или блок на хабе, не смешивать с ledger. TECH-DESIGN помечает глубокую аналитику как Pro v2 — в v1.1 достаточно простых процентов занятости из уже существующего календаря.

## Касса: целевой UX волны 1

```
Касса                    [Неделя | 2 недели | Месяц]
1–31 августа

[ Доход  420 ] [ Расход  90 ] [ Итог  330 ]

график  ▇ ▇ ▂ ▇ …   sage = доход, terracotta = расход

Материалы ████░░░░
Аренда    ██░░░░░░

[ Чаевые ] [ Материалы ] [ Аренда ]     [ + Добавить ]

история строк (карточки, как записи)
```

Sheet «Чаевые»: сумма, категория Чаевые, опционально визит, комментарий.  
Sheet «Расход»: сумма, категория, период = выбранный сверху (как в PRD).

Пустой период: те же карточки с нулями + текст «Завершите визит — цена услуги попадёт сюда. Чаевые и лаки запишите сами.»

## Не делать в волне 1

- Chart.js / Recharts / фиолетовые дашборды.
- Кастомный date-range picker (пресеты PRD достаточны).
- Админский просмотр чужой кассы.
- Смена схемы Prisma.
- SSR кассы с cookies в этом PR — отдельная волна 4, чтобы не смешивать auth-prefetch с UI.

## Критерии волны 1

- На мобилке «Касса» в нижней панели без «Ещё».
- Хаб показывает доход/расход/итог за месяц или понятный empty.
- С завершённой записи можно добавить чаевые к этому `bookingId`.
- На кассе есть график периода и разбивка категорий.
- Расход добавляется из sheet, не из вечной простыни полей.
- Клиент по-прежнему не видит кассу.
