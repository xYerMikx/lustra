# Lumira pull requests

Base branch: **`main`**. Integration branch: **`develop`**. Tool: **`gh`**.

## Auth gate

```bash
gh auth status
```

If token invalid / 401 → tell user to run:

```bash
gh auth login -h github.com
```

Prefer HTTPS or SSH to match `git remote`. Do not proceed with PR create until auth works.

## Workflow

```bash
git status
git log <base>..HEAD --oneline
git diff <base>...HEAD --stat
git push -u origin HEAD
```

Then:

| Source → target | Title style | Body |
|---|---|---|
| `develop` → `main` | Release summary of shipped changes | Concrete short bullets under **Summary only** |
| `feature/*` or `fix/*` → `develop` | Short feat/fix summary | Brief what/why under **Summary only** |

### Body rules (hard)

- **Only** a `## Summary` section with short bullets.
- **Do not** add `## Test plan`, checklists, or any footer.
- **Do not** append “Made with …”, “Made by …”, “Generated by Cursor”, co-author trailers, or similar signatures.

### Release PR (`develop` → `main`)

```bash
gh pr create --base main --head develop --title "release: <summary>" --body "$(cat <<'EOF'
## Summary
- bullet
- bullet
EOF
)"
```

### Feature PR → `develop`

```bash
gh pr create --base develop --title "feat(scope): <short>" --body "$(cat <<'EOF'
## Summary
- what changed and why (brief)
EOF
)"
```

Add `--draft` only when the user asks for a draft.

## After create

Paste the PR URL in the reply. End with a **Commit message** suggestion only if code was also changed in the same turn; pure PR-open turns need no fake commit.
